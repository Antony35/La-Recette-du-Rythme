Dans la partie précédente, tu as découvert le principe du live coding :
transformer un programme pendant que la musique joue. Maintenant, à toi de
le faire. Avec une seule ligne de code, tu vas lancer un rythme, le modifier
et entendre le résultat sans arrêter la lecture.

À la fin de ces **20 minutes**, tu sauras utiliser la boucle de travail de
tout le cours : **écrire → évaluer → écouter → recommencer**.

## Comprendre le REPL — 3 min

**REPL** signifie **Read, Evaluate, Print, Loop**, soit « lire, évaluer,
afficher, recommencer ». Ces mots décrivent ce que fait l'environnement
avec ton code.

| Étape | Ce qui se passe |
| --- | --- |
| **Read — lire** | L'environnement lit le code que tu as écrit. |
| **Evaluate — évaluer** | Il exécute les instructions pour construire le motif musical. |
| **Print / Play — afficher / jouer** | Le résultat devient perceptible : dans Strudel, tu l'entends. |
| **Loop — recommencer** | Tu peux proposer une nouvelle version et l'évaluer à nouveau. |

Le mot *Print* désigne habituellement l'affichage d'un résultat. Pour la
musique, on parle aussi de *Play* : le résultat se joue.
[La documentation du REPL Strudel](https://strudel.cc/technical-manual/repl/)
présente cette adaptation au live coding.

Il y a donc deux boucles : **le motif sonore se répète**, et **toi, tu répètes
les gestes d'écriture et d'écoute** pour le faire évoluer.

## Jouer ta première ligne — 4 min

Clique sur **Play** dans le bloc ci-dessous. Au premier clic, l'éditeur et les
sons se chargent : laisse-leur quelques instants. Le code devient ensuite
modifiable directement dans la page. **Stop** permet d'arrêter la lecture.

<StrudelRepl client:visible code={'s("bd*4")'} label="Ton premier rythme" />

Cette ligne se lit ainsi :

- **`s(...)`** choisit le son à jouer ; c'est la forme courte de `sound(...)`.
- **`bd`** signifie *bass drum*, la grosse caisse.
- **`*4`** répète ici ce son quatre fois dans un **cycle**, la durée de référence
  du motif. Une fois ce cycle terminé, le motif recommence.

Les parenthèses et les guillemets font partie de l'écriture : conserve-les.
Pour cette séance, tu n'auras besoin de changer que le chiffre.

> Écoute plusieurs répétitions. Compte « 1, 2, 3, 4 » avec les coups de grosse
> caisse, puis recommence à 1. Repère la régularité du motif avant de le modifier.

## Modifier, puis réévaluer — 7 min

Garde la lecture en cours. Dans l'éditeur, remplace uniquement le `4` par `8` :

```js
s("bd*8")
```

**Attends et écoute avant de faire autre chose.** Le texte a changé, mais
le rythme entendu reste celui de la dernière version évaluée.

Clique dans le code, puis appuie sur **Ctrl + Entrée** pour **réévaluer** :
demander à Strudel de prendre en compte la nouvelle version. Tu entends
alors les coups se rapprocher, sans avoir eu à appuyer sur Stop.

Le cycle conserve sa durée : tu y places maintenant huit coups au lieu de
quatre. Le rythme est plus dense ; le son de grosse caisse reste le même.

> Reviens à `4`, réévalue et écoute. Essaie ensuite `2`, puis `8`, en réévaluant
> à chaque changement. Avant chaque réévaluation, prédis si les coups seront
> plus espacés ou plus rapprochés, puis vérifie à l'oreille.

Le geste essentiel est là : **modifier le texte prépare le changement ;
réévaluer le rend audible**. Tu peux prendre le temps d'écrire pendant que
la version précédente continue de jouer.

Les commandes de l'éditeur et les premiers sons sont également présentés
dans [l'atelier officiel First Sounds](https://strudel.cc/workshop/first-sounds/).

## À toi de conduire la boucle — 4 min

Repars de `s("bd*4")`. Cette fois, réalise une petite transformation en
continu, sans arrêter la lecture entre les étapes.

> 1. Fais jouer quatre coups par cycle et laisse le motif s'installer.
> 2. Prépare une version avec deux coups. Écoute encore la version en cours,
>    puis réévalue au moment de ton choix.
> 3. Passe à huit coups et réévalue pour rendre le rythme plus serré.
> 4. Retrouve les quatre coups de départ, puis termine avec Stop.
>
> Recommence jusqu'à pouvoir enchaîner ces gestes sans relire les consignes.

Si tu n'entends pas le changement, clique bien **dans l'éditeur** avant de
faire Ctrl + Entrée. Si une erreur apparaît, compare ta ligne avec
`s("bd*4")` : vérifie les deux guillemets, les deux parenthèses et l'astérisque,
puis réévalue. Si aucun son ne sort dès le départ, vérifie le volume,
la sortie audio et que l'onglet n'est pas muet.

## Ce qu'il faut retenir — 2 min

Le REPL permet d'essayer une idée et d'en écouter le résultat. Tu n'as pas
besoin d'écrire un morceau entier avant de jouer : une ligne suffit pour
commencer, puis tu la transformes par petites étapes.

> Le code affiche `s("bd*8")`, mais tu entends encore quatre coups par cycle.
> Quel geste manque-t-il ? Explique ensuite avec tes mots les quatre étapes
> du REPL.

  qui joue tant que tu ne l'as pas réévalué.</p>

Dans la partie précédente, vous avez découvert le principe du live coding :
transformer un programme pendant que la musique joue. Maintenant, à vous de
le faire. Avec une seule ligne de code, vous allez lancer un rythme, le modifier
et entendre le résultat sans arrêter la lecture.

À la fin de ces **20 minutes**, vous saurez utiliser la boucle de travail de
tout le cours : **écrire → évaluer → écouter → recommencer**.

## Comprendre le REPL — 3 min

**REPL** signifie **Read, Evaluate, Print, Loop**, soit « lire, évaluer,
afficher, recommencer ». Ces mots décrivent ce que fait l'environnement
avec votre code.

| Étape | Ce qui se passe |
| --- | --- |
| **Read — lire** | L'environnement lit le code que vous avez écrit. |
| **Evaluate — évaluer** | Il exécute les instructions pour construire le motif musical. |
| **Print / Play — afficher / jouer** | Le résultat devient perceptible : dans Strudel, vous l'entendez. |
| **Loop — recommencer** | Vous pouvez proposer une nouvelle version et l'évaluer à nouveau. |

Le mot *Print* désigne habituellement l'affichage d'un résultat. Pour la
musique, on parle aussi de *Play* : le résultat se joue.
[La documentation du REPL Strudel](https://strudel.cc/technical-manual/repl/)
présente cette adaptation au live coding.

Il y a donc deux boucles : **le motif sonore se répète**, et **vous, vous répétez
les gestes d'écriture et d'écoute** pour le faire évoluer.

## Jouer votre première ligne — 4 min

Cliquez sur **Play** dans le bloc ci-dessous. Au premier clic, l'éditeur et les
sons se chargent : laissez-leur quelques instants. Le code devient ensuite
modifiable directement dans la page. **Stop** permet d'arrêter la lecture.

<StrudelRepl client:visible code={'s("bd*4")'} label="Votre premier rythme" />

Cette ligne se lit ainsi :

- **`s(...)`** choisit le son à jouer ; c'est la forme courte de `sound(...)`.
- **`bd`** signifie *bass drum*, la grosse caisse.
- **`*4`** répète ici ce son quatre fois dans un <CourseTerm term="cycle" />, la durée de référence
  du motif. Une fois ce cycle terminé, le motif recommence.

Les parenthèses et les guillemets font partie de l'écriture : conservez-les.
Pour cette séance, vous n'aurez besoin de changer que le chiffre.

> Écoutez plusieurs répétitions. Comptez « 1, 2, 3, 4 » avec les coups de grosse
> caisse, puis recommencez à 1. Repérez la régularité du motif avant de le modifier.

## Modifier, puis réévaluer — 7 min

Gardez la lecture en cours. Dans l'éditeur, remplacez uniquement le `4` par `8` :

```js
s("bd*8")
```

**Attendez et écoutez avant de faire autre chose.** Le texte a changé, mais
le rythme entendu reste celui de la dernière version évaluée.

Cliquez dans le code, puis appuyez sur **Ctrl + Entrée** pour **réévaluer** :
demander à Strudel de prendre en compte la nouvelle version. Vous entendez
alors les coups se rapprocher, sans avoir eu à appuyer sur Stop.

Le cycle conserve sa durée : vous y placez maintenant huit coups au lieu de
quatre. Le rythme est plus dense ; le son de grosse caisse reste le même.

> Revenez à `4`, réévaluez et écoutez. Essayez ensuite `2`, puis `8`, en réévaluant
> à chaque changement. Avant chaque réévaluation, prédisez si les coups seront
> plus espacés ou plus rapprochés, puis vérifiez à l'oreille.

Le geste essentiel est là : **modifier le texte prépare le changement ;
réévaluer le rend audible**. Vous pouvez prendre le temps d'écrire pendant que
la version précédente continue de jouer.

Les commandes de l'éditeur et les premiers sons sont également présentés
dans [l'atelier officiel First Sounds](https://strudel.cc/workshop/first-sounds/).

## À vous de conduire la boucle — 4 min

Repartez de `s("bd*4")`. Cette fois, réalisez une petite transformation en
continu, sans arrêter la lecture entre les étapes.

> 1. Faites jouer quatre coups par cycle et laissez le motif s'installer.
> 2. Préparez une version avec deux coups. Écoutez encore la version en cours,
>    puis réévaluez au moment de votre choix.
> 3. Passez à huit coups et réévaluez pour rendre le rythme plus serré.
> 4. Retrouvez les quatre coups de départ, puis terminez avec Stop.
>
> Recommencez jusqu'à pouvoir enchaîner ces gestes sans relire les consignes.

Si vous n'entendez pas le changement, cliquez bien **dans l'éditeur** avant de
faire Ctrl + Entrée. Si une erreur apparaît, comparez votre ligne avec
`s("bd*4")` : vérifiez les deux guillemets, les deux parenthèses et l'astérisque,
puis réévaluez. Si aucun son ne sort dès le départ, vérifiez le volume,
la sortie audio et que l'onglet n'est pas muet.

## Ce qu'il faut retenir — 2 min

Le <CourseTerm term="repl" /> permet d'essayer une idée et d'en écouter le résultat. Vous n'avez pas
besoin d'écrire un morceau entier avant de jouer : une ligne suffit pour
commencer, puis vous la transformez par petites étapes.

> Le code affiche `s("bd*8")`, mais vous entendez encore quatre coups par cycle.
> Quel geste manque-t-il ? Expliquez ensuite avec vos mots les quatre étapes
> du REPL.
